# Spårhund development rules

Goals:
- Local-first Python MVP
- Modular architecture
- One file = one responsibility
- Easy to debug stepwise
- Prefer simple solutions over abstractions
- Flask + SQLite first
- Avoid premature optimization
- Avoid enterprise patterns unless necessary
- Always explain architecture decisions
- Preserve backward compatibility

Coding style:
- Keep files short
- Add comments for future expansion
- Prefer config-driven logic
- Avoid hidden magic
- Clear logging
- Minimal dependencies

Critical:
This project is for investigative journalism workflows.
Every signal must be explainable and source-backed.
No unsupported conclusions.
